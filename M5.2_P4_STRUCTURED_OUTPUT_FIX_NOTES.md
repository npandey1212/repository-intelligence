# M5.2 P4 Analyst structured-output repair

## Baseline
This is a focused patch against the uploaded `repository-intelligence-multi-agent.zip`
baseline and the M5.2 patch that produced the user's P4 failure. It is not a full
repository snapshot.

## Fix
- Analyst system prompt now explicitly lists every required `ArchitectureFinding` field,
  including `question`, and explicitly says not to return an `InvestigationReport`.
- P4's input message reinforces the required output type.
- P4 retries once only when the exception indicates structured-output validation failure.
  The retry receives the original task and a correction message containing the validation
  error and required fields. It has no repository tools and does not rerun P1-P3.
- If the repair fails, P4 returns `STRUCTURED_OUTPUT_REPAIR_FAILED`; P1-P3 reports remain
  preserved by the graph's existing failure handling.
- Added a regression test for a first response missing `question`, followed by a valid
  `ArchitectureFinding`.

## Verification
- `graph.py` and `tests/test_langgraph_poc.py` compile successfully.
- All notebook code cells compile successfully.
- `pytest -q tests/test_langgraph_poc.py` was skipped because the optional LangChain/
  LangGraph dependencies are not installed in this execution environment. Therefore the
  live structured-output retry is not integration-tested here and needs your configured
  environment to verify.
